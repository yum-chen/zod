It's often useful to associate a schema with some additional *metadata* for documentation, code generation, AI structured outputs, form validation, and other purposes.

## Registries

Metadata in Schema is handled via *registries*. Registries are collections of schemas, each associated with some *strongly-typed* metadata. To create a simple registry:

```ts
import * as Schema   from "schema";

const myRegistry = Schema.registry<{ description: string }>();
```

To register, lookup, and remove schemas from this registry:

```ts
const mySchema = Schema.string();

myRegistry.add(mySchema, { description: "A cool schema!"});
myRegistry.has(mySchema); // => true
myRegistry.get(mySchema); // => { description: "A cool schema!" }
myRegistry.remove(mySchema);
myRegistry.clear(); // wipe registry
```

TypeScript enforces that the metadata for each schema matches the registry's **metadata type**.

```ts
myRegistry.add(mySchema, { description: "A cool schema!" }); // ✅
myRegistry.add(mySchema, { description: 123 }); // ❌
```

> **Special handling for `id`** —  Schema registries treat the `id` property specially. An `Error` will be thrown if multiple schemas are registered with the same `id` value. This is true for all registries, including the global registry.


### `.register()`

> **Note** — This method is special in that it does not return a new schema; instead, it returns the original Schema. No other Schema method does this! That includes `.meta()` and `.describe()` (documented below) which return a new instance.

Schemas provide a `.register()` method to more conveniently add it to a registry.

```ts
const mySchema = Schema.string();

mySchema.register(myRegistry, { description: "A cool schema!" });
// => mySchema
```

This lets you define metadata "inline" in your schemas.

```ts
const mySchema = Schema.object({
  name: Schema.string().register(myRegistry, { description: "The user's name" }),
  age: Schema.number().register(myRegistry, { description: "The user's age" }),
})
```

<Callout>
If a registry is defined without a metadata type, you can use it as a generic "collection", no metadata required.

```ts
const myRegistry = Schema.registry();

myRegistry.add(Schema.string());
myRegistry.add(Schema.number());
```
</Callout>


## Metadata

### `Schema.globalRegistry`

For convenience, Schema provides a global registry (`Schema.globalRegistry`) that can be used to store metadata for JSON Schema generation or other purposes. It accepts the following metadata:

```ts
export interface GlobalMeta {
  id?: string ;
  title?: string ;
  description?: string;
  deprecated?: boolean;
  [k: string]: unknown;
}
```

To register some metadata in `Schema.globalRegistry` for a schema:

```ts
import * as Schema   from "schema";

const emailSchema = Schema.email().register(Schema.globalRegistry, { 
  id: "email_address",
  title: "Email address",
  description: "Your email address",
  examples: ["first.last@example.com"]
});
```

To globally augment the `GlobalMeta` interface, use [*declaration merging*](https://www.typescriptlang.org/docs/handbook/declaration-merging.html). Add the following anywhere in your codebase. Creating a `Schema.d.ts` file in your project root is a common convention.

```ts
declare module "schema" {
  interface GlobalMeta {
    // add new fields here
    examples?: unknown[];
  }
}

// forces TypeScript to consider the file a module
export {}
```

### `.meta()`

For a more convenient approach, use the `.meta()` method to register a schema in `Schema.globalRegistry`. 

<Tabs groupId="lib" items={["Schema", "Schema Mini"]}>
<Tab value="Schema">
```ts
const emailSchema = Schema.email().meta({ 
  id: "email_address",
  title: "Email address",
  description: "Please enter a valid email address",
});
```
</Tab>
<Tab value="Schema Mini">
```ts
const emailSchema = Schema.email().check(
  Schema.meta({ 
    id: "email_address",
    title: "Email address",
    description: "Please enter a valid email address",
  })
);
```
</Tab>
</Tabs>

Calling `.meta()` without an argument will *retrieve* the metadata for a Schema.


```ts
emailSchema.meta();
// => { id: "email_address", title: "Email address", ... }
```

Metadata is associated with a *specific schema instance.* This is important to keep in mind, especially since Schema methods are immutable—they always return a new instance.

```ts
const A = Schema.string().meta({ description: "A cool string" });
A.meta(); // => { description: "A cool string" }

const B = A.refine(_ => true);
B.meta(); // => undefined
```

### `.describe()`

<Callout>
The `.describe()` method remains available, but `.meta()` is the recommended approach.
</Callout>

The `.describe()` method is a shorthand for registering a schema in `Schema.globalRegistry` with just a `description` field.


<Tabs groupId="lib" items={["Schema", "Schema Mini"]}>
<Tab value="Schema">
```ts
const emailSchema = Schema.email();
emailSchema.describe("An email address");

// equivalent to
emailSchema.meta({ description: "An email address" });
```
</Tab>
<Tab value="Schema Mini">
```ts
const emailSchema = Schema.email().check(Schema.describe("An email address"));

// equivalent to
Schema.email().check(Schema.meta({ description: "An email address" }));
```
</Tab>
</Tabs>

## Custom registries

You've already seen a simple example of a custom registry:


```ts
import * as Schema   from "schema";

const myRegistry = Schema.registry<{ description: string };>();
```

Let's look at some more advanced patterns.

### Referencing inferred types

It's often valuable for the metadata type to reference the *inferred type* of a Schema. For instance, you may want an `examples` field to contain examples of the schema's output.

```ts
import * as Schema   from "schema";

type MyMeta = { examples: Schema.$output[] };
const myRegistry = Schema.registry<MyMeta>();

myRegistry.add(Schema.string(), { examples: ["hello", "world"] });
myRegistry.add(Schema.number(), { examples: [1, 2, 3] });
```

The special symbol `Schema.$output` is a reference to the schemas inferred output type (`Schema.infer<typeof schema>`). Similarly you can use `Schema.$input` to reference the input type.

### Constraining schema types

Pass a second generic to `Schema.registry()` to constrain the schema types that can be added to a registry. This registry only accepts string schemas.

```ts
import * as Schema   from "schema";

const myRegistry = Schema.registry<{ description: string }, Schema.SchemaString>();

myRegistry.add(Schema.string(), { description: "A number" }); // ✅
myRegistry.add(Schema.number(), { description: "A number" }); // ❌ 
//             ^ 'SchemaNumber' is not assignable to parameter of type 'SchemaString' 
```
