{/* ## `$SchemaError` */}

In Schema, validation errors are surfaced as instances of the `Schema.core.$SchemaError` class.

> The `SchemaError` class in the `schema` package is a subclass that implements some additional convenience methods.

Instances of `$SchemaError` contain an `.issues` array. Each issue contains a human-readable `message` and additional structured metadata about the issue.


<Tabs groupId="lib" items={["Schema", "Schema Mini"]}>
<Tab value="Schema">
```ts
import * as Schema   from "schema";

const result = Schema.string().safeParse(12); // { success: false, error: SchemaError }
result.error.issues;
// [
//   {
//     expected: 'string',
//     code: 'invalid_type',
//     path: [],
//     message: 'Invalid input: expected string, received number'
//   }
// ]
```
</Tab>
<Tab value="Schema Mini">
```ts
import * as Schema from "schema/mini";

const result = Schema.string().safeParse(12); // { success: false, error: Schema.core.$SchemaError }
result.error.issues;

{/* ## Customization */}

Every issue contains a `message` property with a human-readable error message. Error messages can be customized in a number of ways.


## The `error` param

Virtually every Schema API accepts an optional error message.

```ts
Schema.string("Not a string!");
```

This custom error will show up as the `message` property of any validation issues that originate from this Schema.

```ts
Schema.string("Not a string!").parse(12);
// ❌ throws SchemaError {
//   issues: [
//     {
//       expected: 'string',
//       code: 'invalid_type',
//       path: [],
//       message: 'Not a string!'   <-- 👀 custom error message
//     }
//   ]
// }
```

All `z` functions and schema methods accept custom errors.

<Tabs groupId="lib" items={["Schema", "Schema Mini"]}>
<Tab value="Schema">
```ts
Schema.string("Bad!");
Schema.string().min(5, "Too short!");
Schema.uuid("Bad UUID!");
Schema.iso.date("Bad date!");
Schema.array(Schema.string(), "Not an array!");
Schema.array(Schema.string()).min(5, "Too few items!");
Schema.set(Schema.string(), "Bad set!");
```
</Tab>
<Tab value="Schema Mini">
```ts
Schema.string("Bad!");
Schema.string().check(Schema.minLength(5, "Too short!"));
Schema.uuid("Bad UUID!");
Schema.iso.date("Bad date!");
Schema.array(Schema.string(), "Bad array!");
Schema.array(Schema.string()).check(Schema.minLength(5, "Too few items!"));
Schema.set(Schema.string(), "Bad set!");
```
</Tab>
</Tabs>

If you prefer, you can pass a params object with an `error` parameter instead.

Schema.string({ error: "Bad!" });
Schema.string().min(5, { error: "Too short!" });
Schema.uuid({ error: "Bad UUID!" });
Schema.iso.date({ error: "Bad date!" });
Schema.array(Schema.string(), { error: "Bad array!" });
Schema.array(Schema.string()).min(5, { error: "Too few items!" });
Schema.set(Schema.string(), { error: "Bad set!" });
```
</Tab>
<Tab value="Schema Mini">
```ts

Schema.string().check(Schema.minLength(5, { error: "Too short!" }));

The `error` param optionally accepts a function. An error customization function is known as an **error map** in Schema terminology. The error map will run at parse time if a validation error occurs.

```ts
Schema.string({ error: ()=>`[${Date.now()}]: Validation failure.` });
```

The error map receives a context object you can use to customize the error message based on the validation issue.

```ts
Schema.string({
  error: (iss) => iss.input === undefined ? "Field is required." : "Invalid input."
});
```

For advanced cases, the `iss` object provides additional information you can use to customize the error.

```ts
Schema.string({
  error: (iss) => {
    iss.code; // the issue code
    iss.input; // the input data
    iss.inst; // the schema/check that originated this issue
    iss.schema; // the schema that owns this issue
    iss.path; // the path of the error
  },
});
```

Unlike `iss.inst`, `iss.schema` is always the schema, even when a check originated the issue. Use it to read the owning schema's [metadata](/metadata).

```ts
Schema.config({
  customError: (iss) => {
    const meta = iss.schema && Schema.globalRegistry.get(iss.schema);
    return `${meta?.title ?? "Field"} is invalid.`;
  },
});

Schema.string().min(5).meta({ title: "Password" }).safeParse("abc");
// => "Password is invalid."
```

Depending on the API you are using, there may be additional properties available. Use TypeScript's autocomplete to explore the available properties.

```ts
Schema.string().min(5, {
  error: (iss) => {
    // ...the same as above
    iss.minimum; // the minimum value
    iss.inclusive; // whether the minimum is inclusive
    return `Password must have ${iss.minimum} characters or more`;
  },
});
```

Return `undefined` to avoid customizing the error message and fall back to the default message. (More specifically, Schema will yield control to the next error map in the [precedence chain](#error-precedence).) This is useful for selectively customizing certain error messages but not others.

```ts
Schema.int64({
  error: (issue) => {
    // override too_big error message
    if (issue.code === "too_big") {
      return { message: `Value must be <${issue.maximum}` };
    }

    //  defer to default
    return undefined;
  },
});
```

## Per-parse error customization

To customize errors on a *per-parse* basis, pass an error map into the parse method:

```ts
const schema = Schema.string();

Schema.parse(12, {
  error: iss => "per-parse custom error"
});
```

This has *lower precedence* than any schema-level custom messages.

```ts
const schema = Schema.string({ error: "highest priority" });
const result = Schema.safeParse(12, {
  error: (iss) => "lower priority",
});

result.error.issues;
// [{ message: "highest priority", ... }]
```

The `iss` object is a [discriminated union](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions) of all possible issue types. Use the `code` property to discriminate between them.

> For a breakdown of all Schema issue codes, see the [`schema/v4/core`](/packages/core#issue-types) documentation.

```ts
const result = Schema.safeParse(12, {
  error: (iss) => {
    if (iss.code === "invalid_type") {
      return `invalid type, expected ${iss.expected}`;
    }
    if (iss.code === "too_small") {
      return `minimum is ${iss.minimum}`;
    }
    // ...
  }
});
```

### Include input in issues

By default, Schema does not include input data in issues. This is to prevent unintentional logging of potentially sensitive input data. To include the input data in each issue, use the `reportInput` flag:

```ts
Schema.string().parse(12, {
  reportInput: true
})

// SchemaError: [
//   {
//     "expected": "string",
//     "code": "invalid_type",
//     "input": 12, // 👀
//     "path": [],
//     "message": "Invalid input: expected string, received number"
//   }
// ]
```

## Global error customization

To specify a global error map, use `Schema.config()` to set Schema's `customError` configuration setting:

```ts
Schema.config({
  customError: (iss) => {
    return "globally modified error";
  },
});
```

Global error messages have *lower precedence* than schema-level or per-parse error messages.

The `iss` object is a [discriminated union](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions) of all possible issue types. Use the `code` property to discriminate between them.

> For a breakdown of all Schema issue codes, see the [`schema/v4/core`](/packages/core#issue-types) documentation.

```ts
Schema.config({
  customError: (iss) => {
    if (iss.code === "invalid_type") {
      return `invalid type, expected ${iss.expected}`;
    }
    if (iss.code === "too_small") {
      return `minimum is ${iss.minimum}`;
    }
    // ...
  },
});
```

## Internationalization

To support internationalization of error message, Schema provides several built-in **locales**. These are exported from the `schema/v4/core` package.

> **Note** — The regular `schema` library loads the `en` locale automatically. Schema Mini does not load any locale by default; instead all error messages default to `Invalid input`.

<Tabs groupId="lib" items={["Schema", "Schema Mini"]}>
<Tab value="Schema">
```ts
import * as Schema   from "schema";
import { en } from "schema/locales"

Schema.config(en());
```
</Tab>
<Tab value="Schema Mini">
```ts
import * as Schema from "schema/mini"
import { en } from "schema/locales";

Schema.config(en());
```
</Tab>
</Tabs>

To lazily load a locale, consider dynamic imports:

```ts
import * as Schema   from "schema";

async function loadLocale(locale: string) {
  const { default: locale } = await import(`schema/v4/locales/${locale}.js`);
  Schema.config(locale());
};

await loadLocale("fr");
```

All locales are also exported as `Schema.locales`. Rollup and Webpack tree-shake that down to the ones you use; esbuild ([evanw/esbuild#1420](https://github.com/evanw/esbuild/issues/1420)) and Turbopack don't.

With your own translation function, the `error` param is called during `.parse()`, not when the schema is constructed — a schema defined once picks up the current language on every parse. To translate at render time, translate the issue itself: `code` is the key, and the issue's other properties are the interpolation values.

```ts
Schema.string().min(5, { error: (iss) => t("too_short", iss) }); // at parse time
result.error?.issues.map((iss) => t(iss.code, iss)); // at render time
```

## Error precedence

Below is a quick reference for determining error precedence: if multiple error customizations have been defined, which one takes priority? From *highest to lowest* priority:

1. **Check-level error** — An error defined on the individual check that failed.

  ```ts
  Schema.string().min(5, "Too short!");
  ```

2. **Schema-level error** — Any error message "hard coded" into a schema definition. It covers issues raised by the schema's own checks, so it is the fallback when the check defines no error of its own.

  ```ts
  Schema.string("Invalid name").safeParse(12);          // => "Invalid name"
  Schema.string("Invalid name").min(5).safeParse("ab"); // => "Invalid name"
  ```

3. **Per-parse error** — A custom error map passed into the `.parse()` method.

  ```ts
  Schema.string().parse(12, {
    error: (iss) => "My custom error"
  });
  ```

4. **Global error map** — A custom error map passed into `Schema.config()`.

  ```ts
  Schema.config({
    customError: (iss) => "My custom error"
  });
  ```

5. **Locale error map** — A custom error map passed into `Schema.config()`.

  ```ts
  import { en } from "schema/locales";

  Schema.config(en());
