## `Schema.fromJSONSchema()`

<Callout type="warn">
  **Experimental** — The `Schema.fromJSONSchema()` function is experimental and is not considered part of Schema's stable API. It is likely to undergo implementation changes in future releases.
</Callout>

Schema provides `Schema.fromJSONSchema()` to convert a JSON Schema into a Schema Schema.

```ts
import * as Schema   from "schema";

const jsonSchema = {
  type: "object",
  properties: {
    name: { type: "string" },
    age: { type: "number" },
  },
  required: ["name", "age"],
};

const schemaSchema = Schema.fromJSONSchema(jsonSchema);
```


## `Schema.toJSONSchema()`

To convert a Schema schema to JSON Schema, use the `Schema.toJSONSchema()` function.

```ts
import * as Schema   from "schema";

const schema = Schema.object({
  name: Schema.string(),
  age: Schema.number(),
});

Schema.toJSONSchema(schema)
// => {
//   type: 'object',
//   properties: { name: { type: 'string' }, age: { type: 'number' } },
//   required: [ 'name', 'age' ],
//   additionalProperties: false,
// }
```

All schema & checks are converted to their closest JSON Schema equivalent. Some types have no analog and cannot be reasonably represented. See the [`unrepresentable`](#unrepresentable) section below for more information on handling these cases.

```ts
Schema.bigint(); // ❌
Schema.int64(); // ❌
Schema.symbol(); // ❌
Schema.undefined(); // ❌
Schema.void(); // ❌
Schema.date(); // ❌
Schema.map(); // ❌
Schema.set(); // ❌
Schema.transform(); // ❌
Schema.nan(); // ❌
Schema.custom(); // ❌
Schema.number().multipleOf(0); // ❌ the divisor must be finite and non-zero
```


A second argument can be used to customize the conversion logic.

```ts
Schema.toJSONSchema(schema, {
  // ...params
})
```

Below is a quick reference for each supported parameter. Each one is explained in more detail below.

```ts
interface ToJSONSchemaParams {
  /** The JSON Schema version to target.
   * - `"draft-2020-12"` — Default. JSON Schema Draft 2020-12
   * - `"draft-07"` — JSON Schema Draft 7
   * - `"draft-04"` — JSON Schema Draft 4
   * - `"openapi-3.0"` — OpenAPI 3.0 Schema Object */
  target?:
    | "draft-04"
    | "draft-4"
    | "draft-07"
    | "draft-7"
    | "draft-2020-12"
    | "openapi-3.0"
    | ({} & string)
    | undefined;

  /** A registry used to look up metadata for each Schema. 
   * Any schema with an `id` property will be extracted as a $def. */
  metadata?: $SchemaRegistry<Record<string, any>>;

  /** How to handle unrepresentable types.
   * - `"throw"` — Default. Unrepresentable types throw an error
   * - `"any"` — Unrepresentable types become `{}`
   * - A function — returns the JSON Schema to use, or `"any"`/`"throw"` */
  unrepresentable?:
    | "throw"
    | "any"
    | ((ctx: {
        schemaSchema: $SchemaTypes;
        path: (string | number)[];
        message: string;
      }) => JSONSchema | "throw" | "any" | undefined);

  /** How to handle cycles.
   * - `"ref"` — Default. Cycles will be broken using $defs
   * - `"throw"` — Cycles will throw an error if encountered */
  cycles?: "ref" | "throw";

  /* How to handle reused schemas.
   * - `"inline"` — Default. Reused schemas will be inlined
   * - `"ref"` — Reused schemas will be extracted as $defs */
  reused?: "ref" | "inline";

  /** A function used to convert `id` values to URIs to be used in *external* $refs.
   *
   * Default is `(id) => id`.
   */
  uri?: (id: string) => string;
}
```

### `io`

Some schema types have different input and output types, e.g. `SchemaPipe`, `SchemaDefault`, and coerced primitives. By default, the result of `Schema.toJSONSchema` represents the *output type*; use `"io": "input"` to extract the input type instead.

```ts
const mySchema = Schema.string().transform(val => val.length).pipe(Schema.number());
// SchemaPipe

const jsonSchema = Schema.toJSONSchema(mySchema); 
// => { type: "number" }

const jsonSchema = Schema.toJSONSchema(mySchema, { io: "input" }); 
// => { type: "string" }
```

### `target`

To set the target JSON Schema version, use the `target` parameter. By default, Schema will target Draft 2020-12.   

```ts
Schema.toJSONSchema(schema, { target: "draft-07" });
Schema.toJSONSchema(schema, { target: "draft-2020-12" });
Schema.toJSONSchema(schema, { target: "draft-04" });
Schema.toJSONSchema(schema, { target: "openapi-3.0" });
```

### `metadata`

> If you haven't already, read through the [Metadata and registries](/metadata) page for context on storing metadata in Schema.

In Schema, metadata is stored in registries. Schema exports a global registry `Schema.globalRegistry` that can be used to store common metadata fields like `id`, `title`, `description`, and `examples`.

import * as Schema   from "schema";

const emailSchema = Schema.string().meta({ 
  title: "Email address",
  description: "Your email address",

Schema.toJSONSchema(emailSchema);
// => { type: "string", title: "Email address", description: "Your email address", ... }

All metadata fields get copied into the resulting JSON Schema. 

```ts
const schema = Schema.string().meta({
  whatever: 1234
});

Schema.toJSONSchema(schema);
// => { type: "string", whatever: 1234 }
```

Metadata takes precedence over the keywords Schema generates.

```ts
Schema.toJSONSchema(Schema.string().meta({ type: "number" }));
// => { type: "number" }

Schema.toJSONSchema(Schema.date().meta({ type: "string", format: "date-time" }), { unrepresentable: "any" });
// => { type: "string", format: "date-time" }
```

To drop metadata entirely, pass an empty registry: `Schema.toJSONSchema(schema, { metadata: Schema.registry() })`. To modify a generated schema, use [`override`](#override).

### `unrepresentable`

The following APIs are not representable in JSON Schema. By default, Schema will throw an error if they are encountered. It is unsound to attempt a conversion to JSON Schema; you should modify your schemas  as they have no equivalent in JSON. An error will be thrown if any of these are encountered.

```ts
Schema.bigint(); // ❌
Schema.int64(); // ❌
Schema.symbol(); // ❌
Schema.undefined(); // ❌
Schema.void(); // ❌
Schema.date(); // ❌
Schema.map(); // ❌
Schema.set(); // ❌
Schema.transform(); // ❌
Schema.nan(); // ❌
Schema.custom(); // ❌
Schema.number().multipleOf(0); // ❌ the divisor must be finite and non-zero
```

By default, Schema will throw an error if any of these are encountered. 

```ts
Schema.toJSONSchema(Schema.bigint());
// => throws Error
```

You can change this behavior by setting the `unrepresentable` option to `"any"`. This will convert any unrepresentable type to `{}` (the equivalent of `unknown` in JSON Schema), and drop an unrepresentable check from the schema that carries it.

```ts
Schema.toJSONSchema(Schema.bigint(), { unrepresentable: "any" });
// => {}

Schema.toJSONSchema(Schema.number().multipleOf(0), { unrepresentable: "any" });
// => { type: "number" }
```

To decide case by case, pass a function instead. It's called for each unrepresentable schema encountered. Return a JSON Schema to use in its place, `"any"`, or `"throw"` (the default when you return nothing).

```ts
Schema.toJSONSchema(Schema.object({ createdAt: Schema.date(), id: Schema.bigint() }), {
  unrepresentable: ({ schemaSchema }) =>
    schemaSchema._schema.def.type === "date" ? { type: "string", format: "date-time" } : "throw",
});
// => throws Error (BigInt cannot be represented in JSON Schema)
```

The handler also receives the `path` of the schema and the `message` Schema would have thrown, and any error it throws propagates, so you can report unrepresentable types in your own words.

```ts
Schema.toJSONSchema(schema, {
  unrepresentable: ({ path, message }) => {
    throw new Error(`${message} (at /${path.join("/")})`);
  },
});
```

Two schemas can share a `schemaSchema` but not a `message` — an `undefined` member and a `bigint` member of the same literal both arrive as the literal — so branch on `message` to tell those apart.

A default *value* that can't be serialized to JSON goes through the same handler, as the `.default()` Schema. Under `"any"` the default is dropped and the rest of the schema is emitted as usual; return a JSON Schema to supply your own.

```ts
Schema.toJSONSchema(Schema.bigint().default(0n), {
  unrepresentable: ({ schemaSchema }) => {
    const def = schemaSchema._schema.def;
    if (def.type === "bigint") return { type: "integer", format: "int64" };
    if (def.type === "default") return { default: String(def.defaultValue) };
    return "throw";
  },
});
// => { type: "integer", format: "int64", default: "0" }
```

Returning a JSON Schema for a literal replaces the whole literal, dropping its representable members: `Schema.literal(["a", 1n])` becomes just what you returned, and `"a"` is gone. Return `"any"` instead to keep the existing per-value behavior.

### `cycles`

How to handle cycles. If a cycle is encountered as `Schema.toJSONSchema()` traverses the schema, it will be represented using `$ref`. 

```ts
const User = Schema.object({
  name: Schema.string(),
  get friend() {
    return User;
  },
});

Schema.toJSONSchema(User);
// => {
//   type: 'object',
//   properties: { name: { type: 'string' }, friend: { '$ref': '#' } },
//   required: [ 'name', 'friend' ],
//   additionalProperties: false,
// }
```

If instead you want to throw an error, set the `cycles` option to `"throw"`.

```ts
Schema.toJSONSchema(User, { cycles: "throw" });
// => throws Error
```


### `reused`

How to handle schemas that occur multiple times in the same Schema. By default, Schema will inline these schemas. 

```ts
const name = Schema.string();
const User = Schema.object({
  firstName: name,
  lastName: name,
});

Schema.toJSONSchema(User);
// => {
//   type: 'object',
//   properties: { 
//     firstName: { type: 'string' }, 
//     lastName: { type: 'string' } 
//   },
//   required: [ 'firstName', 'lastName' ],
//   additionalProperties: false,
// }
```

Instead you can set the `reused` option to `"ref"` to extract these schemas into `$defs`.

```ts
Schema.toJSONSchema(User, { reused: "ref" });
// => {
//   type: 'object',
//   properties: {
//     firstName: { '$ref': '#/$defs/__schema0' },
//     lastName: { '$ref': '#/$defs/__schema0' }
//   },
//   required: [ 'firstName', 'lastName' ],
//   additionalProperties: false,
//   '$defs': { __schema0: { type: 'string' } }
// }
```

### `override`

To define some custom override logic, use `override`. The provided callback has access to the original Schema schema and the default JSON Schema. *This function should directly modify `ctx.jsonSchema`.*


```ts
const mySchema = /* ... */
Schema.toJSONSchema(mySchema, {
  override: (ctx)=>{
    ctx.schemaSchema; // the original Schema schema
    ctx.jsonSchema; // the default JSON Schema

    // directly modify
    ctx.jsonSchema.whatever = "sup";
  }
});
```

Note that unrepresentable types will throw an `Error` before this function is called. To represent one of them, use [`unrepresentable`](#unrepresentable) — a handler there substitutes a type without disabling the error for the others. Setting `unrepresentable: "any"` alongside `override` also works, but erases every unrepresentable type.

```ts
// support Schema.date() as ISO datetime strings
const result = Schema.toJSONSchema(Schema.date(), {
  unrepresentable: "any",
  override: (ctx) => {
    const def = ctx.schemaSchema._schema.def;
    if(def.type ==="date"){
      ctx.jsonSchema.type = "string";
      ctx.jsonSchema.format = "date-time";
    }
  },
});
```


## Conversion

Below are additional details regarding Schema's JSON Schema conversion logic.

### String formats

Schema converts the following schema types to the equivalent JSON Schema `format`:

```ts
// Supported via `format`
Schema.email(); // => { type: "string", format: "email" }
Schema.iso.datetime(); // => { type: "string", format: "date-time" }
Schema.iso.date(); // => { type: "string", format: "date" }
Schema.iso.duration(); // => { type: "string", format: "duration" }
Schema.ipv4(); // => { type: "string", format: "ipv4" }
Schema.ipv6(); // => { type: "string", format: "ipv6" }
Schema.uuid(); // => { type: "string", format: "uuid" }
Schema.guid(); // => { type: "string", format: "uuid" }
Schema.url(); // => { type: "string", format: "uri" }
```

The `local: true` and `precision: -1` variants of `Schema.iso.datetime()` fall back to `pattern`, since RFC 3339 `date-time` requires both an offset and seconds.

These schemas are supported via `contentEncoding`:

```ts
Schema.base64(); // => { type: "string", contentEncoding: "base64" }
```

All other string formats are supported via `pattern`:

```ts
Schema.iso.time();
Schema.base64url();
Schema.cuid();
Schema.emoji();
Schema.nanoid();
Schema.cuid2();
Schema.ulid();
Schema.cidrv4();
Schema.cidrv6();
Schema.mac();
Schema.currencyCode();
```

### Numeric types

Schema converts the following numeric types to JSON Schema:

```ts
// number
Schema.number(); // => { type: "number" }
Schema.float32(); // => { type: "number", exclusiveMinimum: ..., exclusiveMaximum: ... }
Schema.float64(); // => { type: "number", exclusiveMinimum: ..., exclusiveMaximum: ... }

// integer
Schema.int(); // => { type: "integer" }
Schema.int32(); // => { type: "integer", exclusiveMinimum: ..., exclusiveMaximum: ... }
```

### Object schemas

By default, `Schema.object()` schemas contain `additionalProperties: "false"`. This is an accurate representation of Schema's default behavior, as plain `Schema.object()` schema strip additional properties.

```ts
import * as Schema   from "schema";

const schema = Schema.object({
  name: Schema.string(),
  age: Schema.number(),
});

Schema.toJSONSchema(schema)
// => {
//   type: 'object',
//   properties: { name: { type: 'string' }, age: { type: 'number' } },
//   required: [ 'name', 'age' ],
//   additionalProperties: false,
// }
```

When converting to JSON Schema in `"input"` mode, `additionalProperties` is not set. See the [`io` docs](#io) for more information.

```ts
import * as Schema   from "schema";

const schema = Schema.object({
  name: Schema.string(),
  age: Schema.number(),
});

Schema.toJSONSchema(schema, { io: "input" });
// => {
//   type: 'object',
//   properties: { name: { type: 'string' }, age: { type: 'number' } },
//   required: [ 'name', 'age' ],
// }
```

By contrast: 

- `Schema.looseObject()` will *never* set `additionalProperties: false`
- `Schema.strictObject()` will *always* set `additionalProperties: false`


### File schemas

Schema converts `Schema.file()` to the following OpenAPI-friendly schema:

```ts
Schema.file();
// => { type: "string", format: "binary", contentEncoding: "binary" }
```

Size and MIME checks are also represented:

```ts
Schema.file().min(1).max(1024 * 1024).mime("image/png");
// => {
//   type: "string",
//   format: "binary",
//   contentEncoding: "binary",
//   contentMediaType: "image/png",
//   minLength: 1,
//   maxLength: 1048576,
// }
```


### Nullability

Schema converts `Schema.null()` to `{ type: "null" }` in JSON Schema.

```ts
Schema.null();
// => { type: "null" }
```

Note that `Schema.undefined()` is unrepresentable in JSON Schema (see [below](#unrepresentable)).

Similarly, `nullable` adds `"null"` to the set of accepted types. Inner schemas that can't be written as a bare type fall back to `anyOf`:

```ts
Schema.nullable(Schema.string());
// => { type: ["string", "null"] }

Schema.nullable(Schema.string().min(5));
// => { anyOf: [{ type: "string", minLength: 5 }, { type: "null" }] }
```

Optional schemas are represented as-is, though they are decorated with an `optional` annotation.

```ts
Schema.optional(Schema.string());
// => { type: "string" }
```

## Registries

Passing a schema into `Schema.toJSONSchema()` will return a *self-contained* JSON Schema. 

In other cases, you may have a set of Schema schemas you'd like to represent using multiple interlinked JSON Schemas, perhaps to write to `.json` files and serve from a web server. 

```ts
import * as Schema   from "schema";

const User = Schema.object({
  name: Schema.string(),
  get posts(){
    return Schema.array(Post);
  }
});

const Post = Schema.object({
  title: Schema.string(),
  content: Schema.string(),
  get author(){
    return User;
  }
});

Schema.globalRegistry.add(User, {id: "User"});
Schema.globalRegistry.add(Post, {id: "Post"});
```

To achieve this, you can pass a [registry](/metadata#registries) into `Schema.toJSONSchema()`. 

> **Important** — All schemas should have a registered `id` property in the registry! Any schemas without an `id` will be ignored. 

```ts
Schema.toJSONSchema(Schema.globalRegistry);
// => {
//   schemas: {
//     User: {
//       id: 'User',
//       type: 'object',
//       properties: {
//         name: { type: 'string' },
//         posts: { type: 'array', items: { '$ref': 'Post' } }
//       },
//       required: [ 'name', 'posts' ],
//       additionalProperties: false,
//     },
//     Post: {
//       id: 'Post',
//       type: 'object',
//       properties: {
//         title: { type: 'string' },
//         content: { type: 'string' },
//         author: { '$ref': 'User' }
//       },
//       required: [ 'title', 'content', 'author' ],
//       additionalProperties: false,
//     }
//   }
// }
```

By default, the `$ref` URIs are simple relative paths like `"User"`. To make these absolute URIs, use the `uri` option. This expects a function that converts an `id` to a fully-qualified URI.

```ts
Schema.toJSONSchema(Schema.globalRegistry, {
  uri: (id) => `https://example.com/${id}.json`
});
// => {
//   schemas: {
//     User: {
//       id: 'User',
//       type: 'object',
//       properties: {
//         name: { type: 'string' },
//         posts: {
//           type: 'array',
//           items: { '$ref': 'https://example.com/Post.json' }
//         }
//       },
//       required: [ 'name', 'posts' ],
//       additionalProperties: false,
//     },
//     Post: {
//       id: 'Post',
//       type: 'object',
//       properties: {
//         title: { type: 'string' },
//         content: { type: 'string' },
//         author: { '$ref': 'https://example.com/User.json' }
//       },
//       required: [ 'title', 'content', 'author' ],
//       additionalProperties: false,
//     }
//   }
// }
```
